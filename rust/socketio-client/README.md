# socketrpc-socketio-client

The Socket.IO v5 / Engine.IO v4 client the Rust clients generated by socketrpc-gen
are written against. It speaks WebSocket only, with JSON packets only (no HTTP
long-polling, no binary attachments). Every Socket.IO v4 server accepts a direct
WebSocket connection unless it was configured to allow polling only.

```toml
socketrpc-socketio-client = { git = "https://github.com/nguyenvanduocit/socketrpc-gen" }
```

Enable `rustls` or `native-tls` for `wss://`.

```rust
use socketrpc_socketio_client::{connect, Event, Options};

let (socket, mut events) = connect(Options::new("http://localhost:3000")).await?;
let answer = socket.emit_with_ack("echo", &[serde_json::json!("hi")], Duration::from_secs(5)).await?;
while let Some(event) = events.recv().await {
    if let Event::Message { event, args, ack: Some(ack) } = event {
        ack.send(&[serde_json::json!("reply")])?;
    }
}
```

## Why not an existing crate

`rust_socketio` 0.6 passes no acknowledgement id to event handlers, so it cannot
answer a server's call. Its fork `tf-rust-socketio` 0.9 can, but both draw
acknowledgement ids at random from `0..999`, so two calls in flight can be answered
with each other's result. Both also spawn a task per inbound packet, which loses
arrival order. Generated clients need all three guarantees below.

## Guarantees

- **Ordered delivery.** Every inbound event reaches `Events` in arrival order, from one
  reader task.
- **Unique acknowledgement ids.** A per-socket counter.
- **No buffering across a disconnect.** `emit` / `emit_with_ack` decide send-or-refuse
  under the lock the connection lifecycle takes: a call made while disconnected fails with
  `Error::Disconnected` and is never sent later, and a call in flight fails the moment its
  connection drops.
- **Session-bound replies.** An `Ack` answers only on the connection its event arrived on.
- **Payload limit.** A frame larger than the server's advertised `maxPayload` is refused
  with `Error::PayloadTooLarge` instead of being written.
- **Reconnects** with exponential backoff (`reconnect_delay` up to `reconnect_delay_max`)
  after a dropped transport or a ping timeout. Never after the server disconnects the
  socket or refuses the namespace, as in socket.io-client. `Event::Connect` reports a
  reconnect; `connect` returning reports the first connection.
- **Closing.** `Socket::close`, or dropping the last `Socket` clone, disconnects and stops
  reconnecting.
